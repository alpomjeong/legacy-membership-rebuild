# 운영 배포 가이드 — 로컬 PC 서버 (네이티브, 외부 접속 + PWA)

절 PC 1대를 상시 서버로 두고 **네이티브(PostgreSQL 16 + Node 20, Docker 없음)** 로 구동한다.
설치·실행은 `infra/native/네이티브-설치-가이드.md` 를 먼저 따르고, 이 문서는 **운영(상시 가동·외부 HTTPS·백업)** 을 다룬다.
PC 웹은 Node 가 API 와 같은 포트(기본 8080)로 서빙하고, 모바일은 **네이티브 앱(Expo)** 을 쓴다.

> 로컬(같은 와이파이)만 쓸 거면 3·4단계(터널)를 건너뛰고 `http://<PC LAN IP>:8080` 으로 접속.

---

## 1. 서버 상시 가동 (Windows)

- **윈도우 서비스 등록(권장)**: nssm 으로 `infra\native\start.bat` 등록 — 가이드 §5.
  (또는 시작프로그램에 `start.bat` 바로가기)
- **PC 자동 로그인**: `netplwiz` → 자동 로그인 설정(무인 재부팅 대비).
- **절전 끄기**: 설정 → 전원 → 화면/절전 "안 함", *추가 전원 설정*에서 최대 절전 해제.
  (절전 시 야간 자동 백업·외부 접속이 끊긴다.)
- **PostgreSQL 서비스**: 설치 기본이 자동 시작 — `services.msc` 에서 `postgresql-x64-16` 자동 확인.
- (권장) UPS(무정전 전원) — 정전 시 DB 손상 방지.

## 2. 시크릿 설정 (최초 1회, 필수)

```powershell
copy infra\native\.env.example infra\native\.env
```

`infra\native\.env` 를 채운다. **`APP_ENV=production` 이면 기본/미설정 시크릿일 때 API 가 부팅을 거부**(fail-closed):

- `APP_ENV=production`
- `DATABASE_URL` — DB 비번은 **URL 예약문자(/ @ : # ? %) 금지** → hex 권장:
  `openssl rand -hex 32`  (PowerShell: `-join ((1..32)|%{'{0:x2}' -f (Get-Random -Max 256)})`)
- `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET` — 서로 다른 강한 랜덤값
  (PowerShell: `[Convert]::ToBase64String((1..48 | % { Get-Random -Max 256 }))`)
- `JUMIN_ENC_KEY` — 주민번호 암호화 키(강한 랜덤값)
- 반영: `start.bat`(또는 nssm 서비스) 재시작. 부팅 실패 시 로그의 `[보안]` 메시지 확인.
- **관리자 계정**: 최초 로그인한 `admin` 의 비밀번호를 즉시 변경(최초 변경 강제 지원).

## 3. 도메인 + Cloudflare Tunnel (외부 HTTPS)

포트포워딩·고정IP 없이 `https://temple.<도메인>` 으로 어디서나 접속. **cloudflared.exe(네이티브)** 를 쓴다.

1. 도메인 1개 준비 → Cloudflare 에 등록(네임서버 이관).
2. **Zero Trust → Networks → Tunnels → Create tunnel** → Windows용 설치 명령/토큰 발급.
3. 서버 PC 에 cloudflared 설치 + 서비스 등록(대시보드가 안내하는 한 줄):
   ```powershell
   cloudflared.exe service install <토큰>
   ```
4. **Public Hostname** 매핑(대시보드): `temple.<도메인>` → `http://localhost:8080`
5. 폰/외부 PC 에서 `https://temple.<도메인>` 접속 확인.

> 도메인 구매 전 임시 테스트: `cloudflared tunnel --url http://localhost:8080`
> → 랜덤 `https://*.trycloudflare.com` URL 발급(재시작마다 변경 — 테스트 전용).
> 대안: 도메인 없이 안정 URL 이 필요하면 Tailscale Funnel 검토.

## 4. 접속 URL / CORS

- PC 웹은 Node 가 같은 오리진으로 서빙 → CORS 설정 불필요.
- 네이티브 앱/타 오리진에서 API 를 직접 호출할 때만 `infra\native\.env` 의
  `CORS_ALLOWED_ORIGINS` 에 해당 오리진 지정.
- 폰 브라우저: `https://temple.<도메인>` 접속 → 메뉴 *홈 화면에 추가* 로 PWA 설치도 가능.

## 5. 데이터 안전 (로컬 PC 최대 리스크)

- DB 는 이 PC 의 PostgreSQL 1곳 → **PC 고장 = 소실**. 반드시 오프사이트 사본 유지.
- 자동 백업: 웹 **백업 관리 → 자동 백업 스케줄**(매일 시각 지정). 산출물은
  `BACKUP_DIR`(기본 `앱폴더\data\backups\full\*.dump`) — 백업은 AES-256-GCM 암호화됨.
- **백업 저장 위치 변경**: `infra\native\.env` 에 `BACKUP_DIR=D:\temple-backups`
  (또는 `\\NAS\share\temple`) 한 줄 → 재시작. 현재 위치는 웹 **백업 관리** 상단 카드에서 확인.
- **백업 폴더 바로 열기**: 서버 PC 에서 `infra\backup\백업폴더-열기.bat` 더블클릭.
- **오프사이트 복사 자동화**: `infra\backup\offsite-sync.bat "E:\temple-offsite"` 를
  작업 스케줄러에 매일 1회 등록(자동 백업 시각 이후). USB/NAS/클라우드 동기폴더로 복사.
- 업로드 이미지 폴더(`STORAGE_DIR`, 기본 `앱폴더\data\uploads`)도 함께 복사 대상.
- 복원 테스트를 주기적으로(웹 복원 → 데이터 확인) 수행해 백업 유효성 검증.

## 6. 최초 세팅 순서 (요약)

1. PostgreSQL·Node 설치 + 빌드(가이드 §1~2) → 2. `.env` 시크릿 채우기 → 3. `start.bat` 기동
→ 4. `admin` 비번 변경 → 5. (레거시 있으면) 관리자 **초기 데이터 이관** 실행
→ 6. 자동 백업 스케줄 + 오프사이트 등록 → 7. (외부 필요 시) 도메인 + Cloudflare Tunnel
→ 8. 폰에 네이티브 앱 설치(`mobile/` EAS 빌드, 아래 §8).

## 7. 업데이트 절차

```powershell
git pull                     # dev 최신
cd backend;  pnpm install; pnpm prisma generate; pnpm build; cd ..
cd frontend; pnpm install; pnpm build; cd ..
# 재시작: nssm restart TempleMembership  (또는 start.bat 재실행 — 마이그레이션·시드 자동)
```

## 8. 네이티브 앱 (모바일)

- `EXPO_PUBLIC_API_BASE=https://temple.<도메인>/api/v1` 로 EAS 빌드(`mobile/` 가이드 참고).
- iOS: Apple 개발자 계정 + TestFlight / Android: APK 또는 Play.
- 기일 알림 푸시: Expo Push(백엔드 구현됨) — HTTPS 필수(iOS ATS·Android cleartext 차단) → 3단계 터널 URL 사용.
