# 설치·운영 가이드 — 아무것도 안 깔린 새 PC 기준

절 PC 1대에 **PostgreSQL + Node** 만으로 구동한다. Docker·Redis·MinIO 불필요.
구성: **PostgreSQL(DB) + Node(API + 웹화면을 같은 포트로 서빙) + 로컬 파일 저장**.

이 문서는 **윈도우만 깔린 백지 PC** 를 기준으로 처음부터 끝까지 적었다.
Git·Node·PostgreSQL 을 미리 깔 필요 없다 — 설치 스크립트가 알아서 깐다.

---

## 준비물 체크리스트

| | 항목 | 비고 |
|---|---|---|
| □ | **Windows 10/11 PC** | 이 PC 가 서버 겸 사용 PC 가 된다 |
| □ | **관리자 권한 계정** | 설치 중 UAC 동의창이 몇 번 뜬다 |
| □ | **인터넷 연결** | 설치 파일 내려받는 동안만 필요 |
| □ | 디스크 여유 **5GB 이상** | PostgreSQL + Node + 소스 + 데이터 |
| □ | `reference-seed-private.sql` | **별도 전달받는 파일.** 4단계에서 사용 |
| □ | `회원데이터_*.xlsx` | 레거시에서 뽑은 엑셀. 5단계에서 업로드 |

> 마지막 두 파일은 개인정보가 들어 있어 리포에 넣지 않는다. USB·카톡 등으로 따로 받는다.

### 설치되는 것 (스크립트가 자동으로)
- **Git** — 소스 업데이트용
- **Node 20 LTS** + **pnpm 10.34.3** — 앱 실행/빌드
- **PostgreSQL 16** — 데이터베이스

이미 깔려 있으면 건너뛴다. 여러 번 실행해도 안전하다(멱등).

## 1단계 — 소스 받기

백지 PC 에는 Git 이 없으므로 **ZIP 으로 받는다.**

1. 브라우저로 https://github.com/alpomjeong/temple-membership-install 접속
2. 초록색 **Code** 버튼 → **Download ZIP**
3. 받은 파일 우클릭 → **압축 풀기**
4. 풀린 폴더(`temple-membership-install-main`)를 원하는 위치로 옮긴다

권장 위치: `C:\temple` — 짧을수록 좋다.
(폴더 이름·경로에 한글이나 공백이 있어도 동작하지만, 짧은 경로가 문제 소지가 적다.)

> **Git 이 이미 있다면** ZIP 대신:
> ```
> git clone https://github.com/alpomjeong/temple-membership-install.git C:\temple
> ```
> ZIP 으로 받아도 상관없다. 설치 스크립트가 `.git` 이 없으면 "이미 받은 소스로 진행" 하고 넘어간다.
> (다만 나중에 업데이트가 편하려면 Git 설치 후 clone 쪽이 낫다 — §9 참고)

## 2단계 — 원클릭 설치

폴더 안에서 아래 파일을 **더블클릭**한다.

```
infra\native\newpc-install.bat
```

검은 창이 뜨고 1~7단계가 순서대로 진행된다. **전체 10~30분** (인터넷 속도와 PostgreSQL 설치 시간에 좌우).

| 단계 | 하는 일 | 걸리는 시간 |
|---|---|---|
| 1/7 | 사전요건 확인 → 없으면 winget 으로 Git·Node·pnpm·PostgreSQL 16 설치 | 5~20분 |
| 2/7 | DB 계정(`temple`)·데이터베이스(`temple`) 생성, 강한 비밀번호 자동 생성 | 수초 |
| 3/7 | 소스 최신화(`git pull`) — ZIP 으로 받았으면 건너뜀 | 수초 |
| 4/7 | backend·frontend 빌드 | 2~5분 |
| 5/7 | `infra\native\.env` 자동 생성 (JWT·암호화 키를 난수로) | 즉시 |
| 6/7 | DB 스키마 적용 → 기본 시드(admin 계정) → 불사목록 마스터 213종 + 공통코드 | 30초~1분 |
| 7/7 | 방화벽 허용 → 서버 기동 → 포트 열리면 브라우저 자동 실행 | 30초 |

### 설치 중에 뜨는 것들

**UAC(관리자 동의) 창** — Git·Node·PostgreSQL 을 설치할 때만 뜬다. **예**를 누른다.

**"PostgreSQL 슈퍼유저(postgres) 비밀번호 입력"** — PostgreSQL 이 **이미 깔려 있을 때만** 물어본다.
백지 PC 면 안 나온다(자동 생성 후 아래 파일에 저장된다).

```
infra\native\postgres-슈퍼유저-비번.txt
```
> ⚠️ 이 파일은 **안전한 곳으로 옮기고 원본은 지운다.** DB 최고 권한 비밀번호다.

**"방화벽 규칙 자동 등록 실패"** 경고 — 관리자 권한이 아니었을 때 나온다.
폰에서 접속할 게 아니면 무시해도 된다. 필요하면 §7 참고.

### 끝나면

초록색으로 이렇게 찍힌다.

```
============================================================
 완료! 로그인: admin / admin1234  (최초 로그인 시 비밀번호 변경 강제)
 다음: 일괄 업로드 → 불사 건 업로드 로 레거시 엑셀 적재
============================================================
```

브라우저가 `http://localhost:8080` 으로 자동으로 열린다.

## 4단계 — 별도 전달분 넣기 (중요)

전달받은 **`reference-seed-private.sql`** 을 아래 폴더에 **그냥 복사해 넣는다.**

```
<설치폴더>\infra\native\reference-seed-private.sql
```

그리고 서버를 **재시작**(§6의 서버관리 창에서 [재시작], 또는 `start.bat` 다시 실행)하면 자동으로 들어간다.

### 이게 뭔가

불사목록 마스터 237종 중 **24종은 항목명에 시주자 실명이 들어 있다.**
마니차·황금마니차처럼 개별 제작물은 레거시에서 "누구 것"인지 구분하려고 이름에 사람 이름을 박아 관리했기 때문이다.

```
마니차_○○○(20260130)
황금마니차_○○○_20250403(완성)
사천왕중불(광목천왕)_노사장님
```

개인정보라 공개 리포에 넣을 수 없어 파일로 따로 전달한다. 나머지 213종은 리포에 들어 있다.

### 안 넣으면 어떻게 되나

서버는 **정상 기동한다.** 다만 그 24종을 참조하는 **불사 건 342행이 업로드에서 반려**된다
(전체 25,237행 중 나머지 24,895행은 정상 적재). 나중에 파일을 넣고 재시작한 뒤
엑셀을 다시 올리면 채워진다.

파일이 없으면 기동 로그에 이렇게 찍힌다.
```
  [안내] 개인 시주 항목 파일 없음 - 별도 전달분입니다. 없으면 해당 불사 건은 업로드에서 반려됩니다.
```

### 제대로 들어갔는지 확인

관리 → 불사목록 화면의 건수가 **237종**(213 + 24)이면 정상이다.
4단계 전에는 213종이다.

## 5단계 — 실데이터 적재

웹 화면에서 **일괄 업로드** 메뉴로 들어가 엑셀을 올린다.

1. **불사 건 업로드** — `회원데이터_*.xlsx` 선택
2. 회원·포교원장·봉안일은 엑셀 내용대로 **자동 생성**된다
3. 불사목록만 자동 생성하지 않는다 — 마스터에 없는 이름은 오타 방지를 위해 반려한다
   (그래서 4단계를 먼저 해야 한다)

업로드가 끝나면 결과에 성공/반려 행 수가 나온다. **오류 0행**이면 완료다.

> 25,000행 넘는 큰 파일은 몇 분 걸린다. 창을 닫지 말 것.

## 6단계 — 평소 서버 켜고 끄기

### 서버관리 창 (권장)

```
infra\native\서버관리.bat     더블클릭
```

작은 관리 창이 뜬다: **▶ 시작 / ■ 중지 / ↻ 재시작**, 그 아래 **브라우저 열기 / 로그 / 백업 폴더**.
왼쪽 위 점 색으로 상태를 보여준다 — 회색 "중지됨", 노랑 "시작 중…", 초록 "실행 중".

- [▶ 시작] 후 20~30초면 초록색 "실행 중"이 된다 → [브라우저 열기]
- 창을 닫으면 **트레이로 내려간다**(서버는 계속 실행). 트레이 아이콘 **더블클릭**으로 다시 연다
- **"이 PC 켜질 때 서버 자동 시작"** 체크 → 재부팅해도 자동으로 켜진다 ← **켜두는 걸 권장**

### 콘솔로 실행 (문제 진단용)

```
infra\native\start.bat        더블클릭
```
cmd 창에 마이그레이션·시드·기동 로그가 그대로 찍힌다. **창을 닫으면 서버가 꺼진다.**

### 상시 가동 세팅

- 서버관리 창의 자동 시작 체크 + 윈도우 **자동 로그인**(`netplwiz`) → 무인 재부팅에도 복구
- **절전 모드 끄기** (설정 → 전원 → 화면/절전 "안 함")
- 가능하면 **UPS** — 정전 시 DB 손상 방지

## 7단계 — 폰·다른 PC 에서 접속

같은 와이파이 안에서:

1. 서버 PC 의 IP 확인 — cmd 에서 `ipconfig` → `IPv4 주소` (예: `<서버-IP>`)
2. 폰 브라우저에서 `http://<서버-IP>:8080`

**안 열리면 방화벽**이다. 서버 PC 의 관리자 PowerShell 에서:

```powershell
New-NetFirewallRule -DisplayName 'Temple Membership 8080' -Direction Inbound `
  -Action Allow -Protocol TCP -LocalPort 8080 -Profile Private,Domain
```

> 설치 시 관리자 권한이었다면 이미 등록돼 있다(규칙 이름 `Temple Membership 8080`).
> 인터넷(LAN 밖)에서 접속하려면 HTTPS 가 필요하다 — `infra/운영-배포-가이드.md` 참고.

## 8단계 — 백업 (반드시 설정)

DB 가 이 PC 한 곳에만 있다. **PC 가 고장나면 데이터가 전부 사라진다.**

### 자동 백업

`.env` 의 `BACKUP_PG_SCHEDULE=true` 면 매일 자동으로 백업이 돌아간다(기본 새벽 3시).
웹 화면 **관리 → 백업** 에서 수동 백업·복원·다운로드도 된다.

### 백업 도구 (GUI)

```
infra\backup\백업도구.bat      더블클릭
```
지금 백업 / 복원 / 자동백업 시각 변경 / 백업 폴더 열기.

### 오프사이트 복사 (필수)

같은 PC 안의 백업은 PC 가 죽으면 같이 죽는다. **USB·NAS·클라우드로 복사**해야 한다.

```
infra\backup\offsite-sync.bat
```
백업 위치는 기본 `<설치폴더>\data\backups`. 업로드 사진(`data\uploads`)도 같이 챙긴다.

> 상세: `infra/backup/README.md`, `infra/backup/백업-새PC-설치매뉴얼.md`

## 9단계 — 업데이트

**ZIP 으로 받았다면** 새 ZIP 을 받아 덮어쓰거나, Git 을 깔고 clone 으로 갈아타는 게 낫다.
`.env` 와 `data\` 폴더는 절대 덮어쓰지 말 것.

**Git 으로 받았다면** 설치 스크립트를 다시 돌리면 된다 — 최신화·빌드·마이그레이션까지 알아서 한다.

```
infra\native\newpc-install.bat
```
`.env` 가 이미 있으면 **덮어쓰지 않고 유지**한다. DB 도 지우지 않는다.

수동으로 하려면:
```powershell
git pull
cd backend ; pnpm install --strict-peer-dependencies=false ; pnpm prisma generate ; pnpm build ; cd ..
cd frontend ; pnpm install ; pnpm build ; cd ..
```
그다음 서버 재시작.

## 문제 해결

| 증상 | 원인 / 해결 |
|---|---|
| `winget(App Installer)이 없습니다` | Microsoft Store 에서 **앱 설치 관리자** 설치 후 다시 실행 |
| `PostgreSQL 16 설치 실패` | 이전 설치 잔재. 아래 §잔재 정리 참고 |
| `postgres 접속 실패` | 슈퍼유저 비밀번호가 틀림. `postgres-슈퍼유저-비번.txt` 확인 |
| 브라우저에 **연결 거부** | 아직 기동 중일 수 있다. 20~30초 기다렸다 새로고침 |
| `120초 안에 포트가 열리지 않았습니다` | `data\server.log` · `data\server.err.log` 확인 |
| 포트 8080 이 이미 사용 중 | `.env` 의 `PORT=8081` 등으로 변경 후 재시작 (방화벽 규칙도 새 포트로) |
| 불사 업로드가 **전부 반려** | 불사목록 마스터가 비었다. 6단계 로그 확인 후 §참조데이터 수동 적재 |
| 특정 행만 `불사목록 미등록` | 4단계 `reference-seed-private.sql` 미적용일 가능성 |
| 콘솔에 한글이 깨짐 | 표시만 깨진 것. 데이터는 UTF-8 로 정상 저장된다 |
| 폰에서 접속 안 됨 | 방화벽(§7). 또는 폰이 다른 와이파이 |

### 참조데이터 수동 적재

```powershell
$env:PGCLIENTENCODING = 'UTF8'
& "C:\Program Files\PostgreSQL\16\bin\psql.exe" -v ON_ERROR_STOP=1 -d temple -f infra\native\reference-seed.sql
& "C:\Program Files\PostgreSQL\16\bin\psql.exe" -v ON_ERROR_STOP=1 -d temple -f infra\native\reference-seed-private.sql
```
확인: `SELECT count(*) FROM buddhist_service_item WHERE is_deleted=false;` → **237** 기대
(공개분 213 + 별도 전달분 24). `PGCLIENTENCODING=UTF8` 을 빼면 한국어 윈도우에서 한글이 깨져 전량 실패한다.

### PostgreSQL 잔재 정리

EDB 언인스톨러는 데이터 디렉터리를 **일부러 남긴다.** 그 폴더는 ACL 때문에 관리자여도 그냥은 못 지운다.
**재부팅 후** 관리자 PowerShell 에서:

```powershell
Get-Process postgres -EA SilentlyContinue | Stop-Process -Force
sc.exe delete postgresql-x64-16
takeown /F "C:\Program Files\PostgreSQL" /R /D Y
icacls "C:\Program Files\PostgreSQL" /grant *S-1-5-32-544:(F) /T /C
Remove-Item -Recurse -Force "C:\Program Files\PostgreSQL"
Remove-LocalUser -Name postgres   # 있을 때만
```
`*S-1-5-32-544` 는 Administrators 그룹 SID — 윈도우 언어와 무관하게 동작한다.

## 부록 A — 수동 설치 (스크립트를 안 쓸 때)

```powershell
# 1) PostgreSQL 16 설치 후 DB·계정 생성
#    https://www.postgresql.org/download/windows/
CREATE USER temple WITH PASSWORD '강한비번';
CREATE DATABASE <DB_NAME> OWNER <DB_USER>;

# 2) Node 20 LTS 설치 후
npm i -g pnpm@10.34.3

# 3) 빌드
cd backend ; pnpm install --strict-peer-dependencies=false ; pnpm prisma generate ; pnpm build
cd ..\frontend ; pnpm install ; pnpm build

# 4) 설정
copy infra\native\.env.example infra\native\.env
```

`.env` 필수 항목: `DATABASE_URL` · `JWT_ACCESS_SECRET` · `JWT_REFRESH_SECRET` · `JUMIN_ENC_KEY` · `APP_ENV=production`

- 강한 값 생성(PowerShell):
  ```powershell
  $b = New-Object byte[] 48
  ([System.Security.Cryptography.RandomNumberGenerator]::Create()).GetBytes($b)
  [Convert]::ToBase64String($b)
  ```
- **DB 비밀번호에 URL 예약문자(`/ @ : # ? %`) 금지** → hex 권장
- `APP_ENV=production` 이면 기본/약한 시크릿일 때 **부팅을 거부**한다(의도된 안전장치)

그다음 `infra\native\start.bat` 실행.

## 부록 B — 테스트 PC 초기화 (재설치 검증용)

설치를 처음부터 다시 검증할 때 쓴다. **실데이터가 있는 PC 에서는 쓰지 말 것.**

```
infra\native\reset-testpc.bat -Level all -DryRun    ← 뭘 지울지 확인만
infra\native\reset-testpc.bat -Level all            ← 실제 실행 (RESET 입력 필요)
```

| 수준 | 지우는 것 |
|---|---|
| `-Level repo` | `.env` · `node_modules` · `dist` · `data\` |
| `-Level db` | 위 + **DB·롤** (PostgreSQL 프로그램은 유지) |
| `-Level all` | 위 + **pnpm·Node·Git·PostgreSQL 16 + 데이터 디렉터리** |

- 수준을 안 주면 사용법만 찍고 멈춘다(실수 방지)
- 대상 DB 는 같은 폴더 `.env` 의 `DATABASE_URL` 을 따라간다
- `.dump` 파일은 지우기 전에 바탕화면으로 자동 대피시킨다
- 끝나고 **재부팅 한 번** 하면 PATH·서비스 등록까지 깨끗해진다

## 부록 C — 파일·경로 지도

| 경로 | 내용 |
|---|---|
| `infra\native\newpc-install.bat` | 원클릭 설치 |

### 구성 메모
- Redis 없음 → 리포트/엑셀은 동기 생성(체감 동일)
- MinIO 없음 → 업로드는 로컬 파일(`STORAGE_DIR`)
- 웹 화면은 Node 가 `STATIC_DIR`(`frontend\dist`)로 함께 서빙 — 별도 nginx 불필요
- 모바일은 별도 네이티브 앱(`mobile/`) 사용
